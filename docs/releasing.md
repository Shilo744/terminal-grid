# שחרור גרסה ומעבר אליה

תיקיית הפיתוח (`Terminal Grid`) משתנה כל הזמן. את האפליקציה החיה מריצים תמיד מעותק קפוא וממוספר בתיקייה `Terminal Grid Versions` (`V4.1`, `V4.2` ...).
שחרור הוא פקודה אחת, והמעבר אליו הוא הפעלה מחדש אחת של האפליקציה.

## לשחרר

בתיקיית הפיתוח, אחרי שהכול נשמר ב-git (עץ נקי) והבדיקות ירוקות:

```
npm run release -- 4.2
```

מה הפקודה עושה, ובמה היא מסרבת:
- **מסרבת** אם עץ git לא נקי, אם מספר הגרסה לא נראה כמו `4.2`, ואם התיקייה `V4.2` כבר קיימת (שחרור אף פעם לא נדרס).
- מייצאת את ה-commit הנוכחי עם `git archive`: רק קבצים שנמצאים ב-git. לא נכנסים `.duo`, `tests/.tmp`, `.dev`, קבצי מצב, יומנים ופרופילי דפדפן.
- מעתיקה את `node_modules` **העתק אמיתי** (robocopy בעדיפות נמוכה, לא קישור): `npm install` בתיקיית הפיתוח לא יכול לשבור שחרור.
- קובעת את `version` ב-`package.json` של העותק (מה שנראה בתיבת "אודות").
- מריצה את הבדיקות המהירות **בתוך העותק**; אם הן נכשלות, העותק נמחק והשחרור לא נוצר.
- כותבת בתוך העותק `Terminal Grid V4.2.cmd` (מריץ את `start.ps1` שלו על פורט 7791, עם `state.json` ו-`settings.json` משלו לידו) ו-`RELEASE.txt` (commit, תאריך, תוצאת הבדיקות).
- כותבת בתיקיית הגרסאות `Switch live to V4.2.cmd` ומרעננת את `switch-live-to-release.ps1`.

אחרי השחרור מעדכנים שורה בטבלה ב-`VERSIONS.md` (ביד).

## לעבור לשחרור (הפעלה מחדש אחת)

1. בלוח הזוגות לוחצים "השהיה" על כל זוג רץ (זוג פעיל מחזיק את השרת בחיים בכוונה).
2. סוגרים את חלון Terminal Grid. כעשר שניות אחר כך השרת נסגר לבד ושומר את כל המצב.
3. לחיצה כפולה על `Switch live to V4.2.cmd` בתיקיית הגרסאות. הוא מחכה שהשרת ייסגר, מעתיק את `state.json` ו-`settings.json` לשחרור ומפעיל אותו.
4. פותחים את החלון בקיצור הרגיל ולוחצים "המשך" על הזוגות המושהים. הטרמינלים חוזרים עם `--resume`.

מאיפה מגיע המצב: התיקייה שממנה האפליקציה רצה שמרה `state.json` בכיבוי, ולכן יש לה את הקובץ החדש ביותר מבין תיקיית הפיתוח וכל תיקיות `V*` (חוץ מהיעד). הסקריפט מדפיס מי נבחר; `-From V4.1` (או נתיב מלא) בוחר ביד. מצב קודם של היעד נשמר כ-`state.json.before-switch`.

## מפעיל יציב ומצביע הגרסה (T80)

הקיצור בשולחן העבודה ותפריט הקליק הימני מצביעים על `launch-current.ps1` בתיקיית הגרסאות, לא על תיקיית גרסה. המפעיל קורא את השורה היחידה ב-`current.txt` (למשל `V4.7`) ומפעיל את `start.ps1` של אותה גרסה עם אותם פרמטרים (תיקייה, `-Kind`). ככה הקיצור לא צריך להשתנות בין גרסאות.

- המקור של המפעיל הוא `scripts/launch-current.ps1`; `npm run release` מעתיק אותו לתיקיית הגרסאות רק אם הוא חסר (אף פעם לא דורס).
- `Switch live to V<n>.cmd` מעדכן את `current.txt` אחרי שהגרסה החדשה הופעלה בהצלחה (רק כשהמפעיל קיים ליד השחרורים; `-NoStart` לא משנה אותו). **שחרור אינו מעבר**: `release.js` אף פעם לא נוגע ב-`current.txt`.
- חזרה אחורה בלי מעבר מצב: עורכים את `current.txt` לגרסה הקודמת (או מריצים את המעבר לגרסה הקודמת, שמעביר גם את המצב).
- הסקריפטים שבמאגר אף פעם לא נוגעים בקיצור שבשולחן העבודה ולא ברישום (יש על זה בדיקה). הקיצור והרישום מוגדרים ידנית פעם אחת.
- הבדיקה: `tests/server/launcher-pointer.js` (תיקיית גרסאות זמנית עם שתי גרסאות מדומות) ו-`tests/server/release.js`.

## הפעלה עם Windows

הקיצור שנוצר בהגדרות ("הפעלה עם Windows") מצביע על `start.ps1` של התיקייה שהאפליקציה רצה ממנה באותו רגע. אחרי מעבר לשחרור חדש כדאי לכבות ולהדליק את ההגדרה פעם אחת, כדי שהקיצור יצביע על השחרור החדש (אחרת הוא ימשיך להפעיל את התיקייה הקודמת).

## לחזור אחורה

אותו דבר, עם השחרור הקודם: משהים זוגות, סוגרים את החלון, ולוחצים `Switch live to V4.1.cmd`. המצב של הרגע האחרון (מהשחרור החדש) עובר איתך אחורה, והמצב הישן נשאר ב-`state.json.before-switch`.

## מה לא לעשות

- לא לערוך קבצים בתוך תיקיית שחרור: היא קפואה בכוונה. תיקון = commit בתיקיית הפיתוח ושחרור חדש.
- לא להריץ את תיקיית הפיתוח כאפליקציה חיה (פורט 7791) כשיש שחרור. לפיתוח: `npm run dev` (פורט 7795, מצב ב-`.dev/`).
- הבדיקות של `release.js` כותבות רק לתיקייה זמנית (`TG_VERSIONS_DIR`), אף פעם לא לתיקיית הגרסאות האמיתית.
